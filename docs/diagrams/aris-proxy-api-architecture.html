aris-proxy-api 架构全景

一个 Go 实现的 LLM 代理网关与管理后台：承载 OpenAI / Anthropic 协议转发与 7 条跨协议转换路径，向下沉淀会话数据，向上提供管理 API、训练数据导出与 Agentic 客户端接入。以下四张图分别刻画系统分层、转发核心、会话数据生命周期与部署发布拓扑。

01

系统总览

客户端 → 网关 → 应用/领域/基础设施 → 外部依赖 · 三条接入路径（JWT 管理、APIKey 转发、Trace 上报）

02

LLM 代理转发核心链路

入站鉴权 → 双层限流 → 敏感词 → 端点解析 → 跨协议转换 → 传输 → 上游 → 统一收尾 seam（recordModelCall）

03

会话数据生命周期与后台管理

两个写入源（LLM 转发 / Trace 摄取）→ Session 聚合（内容寻址去重）→ 缓存 / 导出 / 查询 / 分享

04

部署与发布拓扑

CI 构建多架构镜像 → GHCR → k3s 集群（2 副本）→ LoadBalancer 暴露；Trace CLI 经 GitHub Releases 分发

分层契约与关键决策

  • 依赖注入 go.uber.org/fx，模块分组 bootstrap/modules/：Infra / Cron / Repository / Application / Handler。
  • 分层契约：handler 只依赖 application/*/port；application 只依赖 domain 接口；domain 只依赖 repository 接口。
  • 全局中间件链：Recover → Metrics → Inflight → Guard → Fgprof → CORS → Compress → Trace → Locale → Log。
  • 优雅关闭 9 步：停 cron → 停协程池 → draining → 停 flusher → 关 HTTP → 同步日志 → 停敏感词同步 → 关 DB → 关 Redis。
  • 异步协程池 pond 双池：storePool + agentPool；SubmitMessageStoreTask / SubmitModelCallAuditTask。

7 条跨协议转发路径

  • OpenAI Chat native · Chat → Anthropic · Response native · Response → Chat · Response → Anthropic · Anthropic Message native · Message → Chat。
  • 3 个 converter：AnthropicProtocolConverter / OpenAIProtocolConverter / ResponseProtocolConverter。
  • 收尾 seam recordModelCall：审计 + Token 扣减（Lua）+ 指标 + 状态归一化；会话落库由相邻 MessageStoreTask 完成。
  • 上游重试：连接错误 / 5xx / 429 可重试（指数退避 + jitter），4xx 不可重试。

校正说明（相对 CONTEXT.md）

  • DI 为 fx（dig 仅间接依赖）；cron 实际注册 4 模块（无 session_summarize）。
  • APIKey 中间件实际从 Authorization: Bearer 提取，JWT 为 HS256 对称签名。
  • AgentRuntime / Sandbox / TurnLoop 仅为规划词汇，仓库内尚无实现。
  • cron 4 模块：session-dedup / soft-delete-purge / think-extract / blocked-hit-sync。
  • 指标：llm_token_usage_total、http_requests_total，经 Flusher 快照写 Redis 后跨 Pod 聚合。
